### Раздел 5: Основные алгоритмы ВАНК (строки 181-350)

#### `decimate_vanc(data, p_num)`
```
Входные данные: 3 канала (V, A, N) с произвольным разрешением
Выход: 3 канала с ровно p_num точек
Алгоритм: разделить на p_num равных блоков, усредлить каждый
```

#### `equalize_vanc_step(data, p_num)` (не используется)
```
Переделывает ВАНК на равномерную ось напряжений
```

#### `avrg_curve(data)`
```
Входные данные: n ВАНК (каждая 3 канала x m точек)
Выход: 1 средняя ВАНК (3 канала x m точек)
Алгоритм: точка за точкой усреднить все ВАНК
```

#### `interpolate(vac, target, channel)`
```
Найти значение в канале channel при напряжении target
Используя линейную интерполяцию между ближайшими точками
```

#### `avrg_interpl_curve(data, p_num)` (сложное усреднение)
```
Усреднить ВАНК с учетом их "смещения" по оси напряжений
Более робустно, чем простое усреднение
```

#### `mean_sq_deviation(vac, ref)`
```
Вычислить метрику качества: насколько vac отличается от ref
Низкое значение → ВАНК хорошего качества
Высокое значение → ВАНК с артефактами, шумная
```

#### `reject_bad_vancs(vancs, ref, crit_dev)`
```
Удалить ВАНК из набора, если их отклонение > crit_dev
Возвращает количество удаленных
```

### Раздел 6: Основная функция обработки (строки 351-500)

#### `process_vancs(...)`

Это **главное ядро программы**. Выполняет полную обработку одного файла ВАНК:

1. **Разбиение на периоды** → определение фазы треугольной волны
2. **Разделение на FW/BW** → две независимые ВАНК из одного сканирования
3. **Применение фазовых сдвигов** → синхронизация каналов
4. **Децимация** → понижение разрешения с усреднением
5. **Построение эталонной ВАНК** → усреднение
6. **Фильтрация по качеству** → удаление плохих ВАНК
7. **Пересчет эталонной** → на отфильтрованных данных
8. **Контроль качества** → проверка, осталось ли что-то

**Входные параметры:**
```cpp
vector<vector<float>>& data        // 3 канала x size точек
float crit_dev                     // Критерий качества
int phase_shift_cur                // Сдвиг канала тока
int phase_shift_n                  // Сдвиг канала шума
int period                         // Полный период развертки
int p_num                          // Выходное разрешение
int VAC_num                        // Номер ВАНК (для отчета)
Timer& tmr                         // Таймер для профилирования
```

**Выход:**
```cpp
pair<vector<vector<float>>, vector<vector<float>>>
  // Первая пара: FW ВАНК (V, A, N)
  // Вторая пара: BW ВАНК (V, A, N)
  // Или (EMPTY_VANC, EMPTY_VANC) если все отклонено
```

### Раздел 7: Сохранение результатов (строки 501-520)

#### `print_avrg_VANCS(VANCS, p_num, tm, path)`

Сохраняет финальные усредненные ВАНК в два текстовых файла:
- `VANC_FW_P{p_num}_S{tm}.dat` — прямое сканирование
- `VANC_BW_P{p_num}_S{tm}.dat` — обратное сканирование

Каждый файл: три столбца (V A N) на строку

### Раздел 8: main() функция (строки 521-700)

#### Структура main():

```
1. Инициализация (OpenMP, приоритет потока, русский язык)
2. Установка параметров по умолчанию
3. Интерактивный ввод параметров (опционально)
4. Проверка наличия файлов и определение диапазона
5. ПАРАЛЛЕЛЬНЫЙ ЦИКЛ (OpenMP) для каждого файла:
   ├─ Чтение трех файлов (V, A, N)
   ├─ Объединение в единую структуру
   ├─ Вызов process_vancs() для обработки
   └─ Добавление результатов в накопители (fw_vancs, bw_vancs)
6. Финальное усреднение и интерполяция на равномерную сетку
7. Финальная строгая фильтрация (crit_dev/100)
8. Сохранение результатов в файлы
9. Вывод общего времени обработки
```

### 1. Одиночная ВАНК:
```cpp
vector<vector<float>> vac;  // vac[3][m]
```

```cpp
vector<vector<vector<float>>> fw_vancs;  // fw_vancs[n][3][p_num]
```

### 3. Полные данные одного файла:
```cpp
vector<vector<float>> data;  // data[3][size]
// data[0] — все напряжения из файла
// data[1] — все токи из файла
// data[2] — все шумы из файла
// size — общее количество отсчетов, прочитанных из файла
```

```

                    ▼
```

## Потоки выполнения и параллелизм

```
Главный поток                    Рабочие потоки (4x)
└─ Инициализация
   │
   ├─ Параметры ввода
   │
   ├─ Проверка файлов
   │
   ├─ #pragma omp parallel for   
   │  │
   │  ├─→ ПОТОК 1: Файл 5       ┐
   │  │  └─ process_vancs()      ├─ Параллельно!
   │  ├─→ ПОТОК 2: Файл 6       ├─ Каждый поток
   │  │  └─ process_vancs()      │  обрабатывает
   │  ├─→ ПОТОК 3: Файл 7       │  свой файл
   │  │  └─ process_vancs()      ├─ независимо
   │  ├─→ ПОТОК 4: Файл 8       │
   │  │  └─ process_vancs()      ┤
   │  │                          ┘
   │  ├─→ ПОТОК 1: Файл 9 (когда готов)
   │  ├─→ ПОТОК 2: Файл 10
   │  └─ ... (круговая раздача файлов)
   │
   ├─ Синхронизация (ждем всех потоков)
   │
   ├─ Финальное усреднение (главный поток)
   │
   └─ Сохранение (главный поток)
```

**Ускорение**: теоретически до 4x (для 4 ядер), практически ~3-3.5x из-за синхронизации и нелинейности нагрузки.

## Ключевые циклы и их роль

| Цикл | Где | Назначение | Сложность |
|------|-----|-----------|-----------|
| **Основной цикл файлов** | main() | Перебирает файлы для обработки | O(N_files) |
| **Цикл по периодам** | process_vancs() | Разбирает файл на периоды | O(size/period) |
| **Цикл по полупериодам** | process_vancs() | Обрабатывает FW и BW | O(period/2) |
| **Цикл по точкам ВАНК** | avrg_curve() | Усреднение | O(n_vancs * points) |
| **Цикл по сетке** | avrg_interpl_curve() | Интерполяция на сетку | O(n_vancs * points * p_num) |
| **Фильтрация** | reject_bad_vancs() | Удаление плохых ВАНК | O(n_vancs * points) |

## Оптимизационные возможности

### 1. Можно ускорить чтение файлов:
- Использовать асинхронный I/O (Windows IOCP)
- Читать файлы в фоне, пока другие обрабатываются

### 2. Можно оптимизировать вычисления:
- Использовать SIMD (SSE/AVX) для векторных операций
- Использовать GPU для интерполяции (когда p_num велико)

### 3. Можно улучшить параллелизм:
- Использовать lock-free структуры вместо vector::insert
- Распределить финальное усреднение на потоки

### 4. Можно снизить потребление памяти:
- Обрабатывать файлы потоком (streaming) вместо полного чтения
- Использовать float32 вместо float64 где возможно (уже используется)

## Рекомендации при модификации кода

### При добавлении новой функции:

1. **Добавить подробный комментарий** с объяснением назначения
2. **Добавить примеры использования** в комментарии
3. **Объяснить входные/выходные параметры** и их диапазоны
4. **Указать сложность** (временную и пространственную)
5. **Протестировать с граничными случаями** (пустые вектора, одна точка и т.д.)

### При изменении process_vancs():

1. **Очень осторожно** — это критическая функция
2. **Проверить на граничные случаи**: period/2 < 0, пустые наборы ВАНК
3. **Обновить комментарии** если меняется алгоритм
4. **Профилировать** — может быть узким местом

### При добавлении новых параметров:

1. **Добавить интерактивный ввод** в main()
2. **Добавить значение по умолчанию**
3. **Задокументировать** в файле параметров
4. **Проверить диапазоны** значений
